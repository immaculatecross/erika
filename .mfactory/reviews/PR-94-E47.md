## BLOCKING

### B1 — The Start gate refuses states nothing resolves; onboarding hands the learner into a wall

**Where.** `app/api/session/start/route.ts:21-27` refuses Start with 409 whenever
`preview.lesson.preparation !== "ready"`. The only path in the product that moves a
lesson from `needed` to `ready` is the Learn-home effect at
`app/(app)/practice/page.tsx:46-57`.

**Trigger A — the first session after onboarding (permanent until the learner navigates away).**
`components/onboarding/welcome-flow.tsx:83` → `router.replace(FIRST_SESSION_PATH)`;
`lib/onboarding/routing.ts:48` defines that as `/practice/session`. The session page POSTs
`/api/session/start` on mount (`app/(app)/practice/session/page.tsx:46`); the 409 becomes
`phase: "error"` at `:50` — *"The session could not be opened just now"* with one **Try again**
button that re-POSTs and 409s again. The Learn home is never rendered, so nothing prepares.

Observed on the built server (build `QrVUFVTAPwF4TbEoiO3ui`, random port `46157`,
`ERIKA_DB_PATH=/tmp/e47db.KsiH/erika.db`, `OPENAI_API_KEY` unset):

```
POST /api/onboarding                        -> 200 {"complete":true}
POST /api/session/start                     -> 409 lesson_not_prepared
POST /api/session/start   (Try again)       -> 409 lesson_not_prepared
GET  /practice ; POST /api/session/prepare  -> 200 {"state":"ready","source":"authored"}
POST /api/session/start                     -> 200
```

**Trigger B — an interrupted preparation blocks Start for 15 minutes.** An empty v2 claim
(process killed, deploy, abandoned request) makes `lessonPreparationState` report `preparing`.
The Learn-home effect POSTs only on `needed` (`app/(app)/practice/page.tsx:46`), so the home
renders "Preparing today's lesson…" and polls without ever re-triggering, and Start 409s until
`ITEM_LESSON_CLAIM_STALE_SECONDS` (15 min, `lib/lessons/item-lessons.ts:279`) elapses.
Reproduced by inserting `('rule:alfabeto-suoni','grammar','colto','',2)` into the disposable DB:
`/api/learn/today` → `lessonPreparation:"preparing"`, `/api/session/start` → 409.

In both triggers `GET /api/session/lesson` serves a complete authored Italian lesson for the
same item the whole time (`app/api/session/lesson/route.ts:27` → `authoredLessonFor`) — the gate
withholds a lesson that is already available, free and offline. The 409 message *"Today's lesson
is still being prepared"* is untrue in both cases.

**Harm:** happy path broken, with an untruthful artifact. A valid, keyless, fresh install is
rejected at the exact moment E-46 deposits the learner in their first session. WO criterion 4
requires keyless paths to "prepare the authored Italian fallback immediately and remain
completable"; D-26 forbids this wall.

**Assumption:** trigger A assumes onboarding runs (any fresh database) and that the learner
follows `router.replace` rather than visiting Today first — the tab bar offers recovery, but
nothing on the error screen says so. Trigger B assumes a preparation is interrupted server-side
and self-heals within 15 minutes. Neither assumes a key, a network, deployed multi-user data,
or a second process.

**Test note (D-14).** `tests/session-routes.test.ts:73-75` asserts this 409 *as the
specification* — "refuses Start until the home preparation trigger resolves authored Italian".
Mutating the guard to `if (false)` makes only that one test fail. Read as a claim about the
world it locks in "Start is refused on a fresh database", and it replaced the criterion-3 test
that asserted a keyless learner gets a real lesson.
