## BLOCKING

### B1 — Native `/end` trusts client `realtimeUsageCostUsd` and bypasses the [T2c] minute floor

- `lib/tutor/money.ts:263-267` — when `usageCostUsd` is any finite number (including `0`), finalize commits `min(usage, reserved)` and **never** applies `estimateTutorSessionUsd(model, billedMinutes)`.
- `app/api/tutor/session/[id]/end/route.ts:47-54` — passes `body.realtimeUsageCostUsd` whenever `Number.isFinite(...)` (so `0` counts).
- `lib/tutor/use-tutor-lab.ts:425-434` and `449-466` — native stop / `pagehide` always send `realtimeUsageCostUsd: nativeSessionUsageUsd.current`, which stays `0` if no turn produced parseable usage (open → End with no Done; or every `response.done` omitted usage).

**Demonstrated sequence:** mint a native lease → connect Realtime (provider cost begins) → End with `{ elapsedSeconds: 600, realtimeUsageCostUsd: 0 }` → pending lease deleted, **committed Realtime row = $0** → month-to-date understates invoice → monthly cap fails open for later spend.

Pre-PR finalize always billed from server-floored minutes; this PR replaces that with a client-supplied figure without a server floor.

**Harm:** fail-open — the hard monthly cap understates real Realtime spend when the client reports `0` (or any understated finite value), so later calls are allowed against headroom the invoice already consumed.  
**Assumption:** a native session reaches `/end` with client-controlled `realtimeUsageCostUsd` (always true today); bites whenever that value is below true provider cost — including the ordinary “connected but no usage accumulated” path, and any under-report.

The module comment at `lib/tutor/money.ts:243-247` still claims [T2c] prevents under-pay; that claim is false once `usageCostUsd` is set.

`tests/tutor-money.test.ts` still exercises finalize **without** usage and expects minute-based estimates. The production native end path always supplies a finite usage number. A regression that commits `$0` for a leased session would not turn these tests red.

### A2 — Concurrent transcript duplicate loses with a budget 402, not `duplicate_turn`

Sequential duplicates correctly 409 (`tests/tutor-turn-routes.test.ts`). If two POSTs interleave across the ffprobe `await` and the loser hits `reserveTranscriptLeg` after the winner reserved, the loser gets `402` / “monthly budget cannot cover” (`lib/tutor/transcript-turn-route.ts:164-168`) rather than `409 duplicate_turn`. No double charge on single-threaded Node (check+insert in `reserveTranscriptLeg` is synchronous), but the refusal is untruthful.

**Assumption:** overlapping same-`tutorId`+`seq` POSTs during probe.
